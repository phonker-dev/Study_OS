# Study OS — настройка и публикация

Статический сайт-«рабочий стол» с расписанием, конспектами, погодой,
папкой «Щитпост» и админкой. Хостится на GitHub Pages, общие данные —
в бесплатном Supabase.

---

## 🔴 Сначала — про утёкший ключ

В прежней версии `supabase.js` лежал ключ вида `sb_secret_…`. Это
**секретный service_role-ключ**: он игнорирует все политики доступа и даёт
полный контроль над базой любому, кто откроет исходники сайта.

**Что сделать прямо сейчас:**

1. Supabase → **Settings → API Keys** → найдите этот ключ → **Revoke** / **Roll**.
2. Скопируйте оттуда же ключ **`anon` `public`** — он и нужен сайту.
3. Вставьте его в [`supabase.js`](supabase.js) в строку `SUPABASE_ANON_KEY`.

Ключ `anon public` публиковать безопасно: без входа в админку он даёт
только чтение (это гарантируют RLS-политики из `supabase-schema.sql`).

Пока ключ не вставлен, сайт **работает в локальном режиме**: расписание,
конспекты, ДЗ и мемы живут в браузере устройства, общими не становятся.
Ничего при этом не ломается.

## 2. Настройка Supabase (10 минут)

1. **Создайте проект** на [supabase.com](https://supabase.com) — бесплатного
   тарифа с запасом хватает.

2. **Создайте таблицы.** SQL Editor → New query → вставьте целиком
   содержимое `supabase-schema.sql` → **Run**. Скрипт создаст три таблицы
   (`schedule`, `day_notes`, `memes`), бакет `memes` для картинок
   и политики доступа «всем читать, админу писать».

3. **Создайте админский аккаунт.** Authentication → Users → **Add user**:
   - Email: `admin@study-os.local`
   - Password: `penis`
   - галочка **Auto Confirm User** — обязательно, иначе вход не сработает.

   Хотите другой e-mail — поменяйте `ADMIN_EMAIL` в начале `app.js`.
   Хотите другой пароль — поменяйте его и здесь, и в `ADMIN_PASSWORD`.

4. **Закройте публичную регистрацию.** Authentication → Sign In / Providers →
   выключите **Allow new users to sign up**. Иначе кто угодно сможет
   зарегистрироваться и получить права на запись.

5. **Пропишите ключи** в `supabase.js`:
   ```js
   const SUPABASE_URL      = 'https://ваш-проект.supabase.co';   // без /rest/v1/
   const SUPABASE_ANON_KEY = 'eyJhbGciOi…';                      // anon public
   ```

6. **Выгрузите расписание в базу.** Откройте сайт → Пуск → Админ-панель →
   пароль `penis` → **«Синхронизировать с БД»**. После этого расписание
   видят все, а не только вы.

## 3. Публикация на GitHub Pages

1. Залейте файлы в репозиторий так, чтобы `index.html` был в корне.
2. Settings → Pages → Build and deployment → **Deploy from a branch**,
   ветка `main`, папка `/ (root)` → Save.
3. Через 1–2 минуты сайт будет по адресу
   `https://ваш-логин.github.io/имя-репозитория/`.

Ограничьте TomTom-ключ по домену в личном кабинете TomTom
(`ваш-логин.github.io`) — тогда чужие сайты не съедят вашу бесплатную квоту.

## 4. Как это работает для пользователей

| Что                | Без Supabase              | С Supabase                          |
|--------------------|---------------------------|-------------------------------------|
| Расписание         | правит любой, локально    | общее; правит только админ          |
| Домашние задания   | локально                  | общие для всех                      |
| Щитпост            | локально, по ссылкам      | общий; файлы в Storage              |
| Конспекты          | всегда локально (личные)  | всегда локально (личные)            |
| Погода и время     | по городу из настроек     | по городу из настроек               |

Кнопки `+`, ✎ и ✕ в расписании показываются только тогда, когда правки
имеют смысл: в локальном режиме — всем, в общем — только вошедшему админу.

## 5. Админка

Пуск → **Админ-панель** → пароль `penis`.

- **Синхронизировать с БД** — выгрузить текущее расписание для всех.
- **Общие заметки (ДЗ)** — по одному полю на день; видны всем в окне
  «Расписание» и в виджете на рабочем столе.
- **Управление мемами** — загрузка файла в Supabase Storage или добавление
  по прямой ссылке; удаление по одному или всё сразу.

> Пароль проверяется в браузере и виден в исходниках — это «замок от
> честных людей». Настоящую защиту даёт вход в Supabase Auth: без него
> RLS не пропустит ни одной записи, даже если пароль подсмотрели.

## 6. Погода, город и время

- Город задаётся в **Панели управления** либо определяется кнопкой
  «Определить город автоматически» (Geolocation API браузера).
- При первом заходе без сохранённого города сайт один раз сам спросит
  разрешение на геолокацию.
- Часовой пояс **не захардкожен**: он приходит вместе с прогнозом
  (`timezone=auto` у Open-Meteo) и сразу применяется к часам в трее,
  к определению «сегодня» и к чётности недели.
- Иконка погоды в трее и в окне — SVG, рисуется кодом; поддержаны ясно,
  малооблачно, пасмурно, туман, морось, дождь, ливень, снег и гроза.

Геолокация работает **только по HTTPS** — на GitHub Pages это так;
на `file://` кнопка выдаст ошибку, это нормально.

---

## 7. Локальный запуск

```bash
python -m http.server 5173
```

Затем откройте `http://localhost:5173`. Через `file://` не заработают
ни `fetch('schedule.json')`, ни геолокация.
